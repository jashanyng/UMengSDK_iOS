# ADR-0001：封装版本等于基础库 UMCommon 的版本

友盟 iOS SDK 由多个独立发版的组件组成（如 `UMCommon 7.7.0`、`UMDevice 3.6.0`、`UMAPM 2.2.1`），而一个 SwiftPM 仓库只有一条 tag 序列，无法同时等于所有组件的版本。我们决定：单仓库发布，**封装版本（tag）严格等于基础库 `UMCommon` 的版本**（不带 `v` 前缀）；随附组件 `UMDevice` 每次发布时取当时上游最新正式版本，其单独更新不产生新封装版本，随下一次 `UMCommon` 发版一并发布；tag 发布后不可变，封装缺陷只能在下一个上游版本修复。

## Considered Options

- **每个组件一个仓库**（tag 各自等于上游版本，仓库间按 podspec 依赖互相依赖）：对齐最彻底，但仓库数量与维护成本随组件增长；当前只需要统计最小集合，收益不足。
- **自有语义化版本 + 对照表**：放弃了“版本号与友盟一致”这一核心诉求。

## Consequences

- `UMDevice` 等随附组件的单独更新会延迟到下一次 `UMCommon` 发版（2026 年 `UMCommon` 约每月一版）。
- 将来若引入发版节奏独立且需及时跟进的组件（如 `UMAPM`、推送、分享），应另建仓库并依赖本仓库，而不是放进本包。
- 每个封装版本所含组件版本记录在 `CHANGELOG.md` 与对应 GitHub Release 说明中。
